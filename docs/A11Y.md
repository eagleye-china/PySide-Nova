# 可访问性手册 — WCAG 2.1 AA 落地（0.16.0 新颁）

> 本文是 a11y 的**规则源**；[A11Y_MATRIX.md](A11Y_MATRIX.md) 是由 `scripts/check_a11y.py`
> 生成的逐类型契约矩阵（生成物，勿手改）。两者冲突时以门禁脚本的判定为准，并回来改本文。

## 1. 为什么单独成一个交付单元

Quasar 2.35.5 **没有 a11y 模块**：Vue 侧靠散写 `aria-*`，无统一令牌、无门禁、无键盘路径约束。
Nova 把它作为差异化能力做成一整层：**语义（Accessible）＋视觉（AA 派生令牌）＋交互（键盘全路径）＋
工程（静态/运行时双门禁）**。这也是 `1.0.0-flagship` 封版验收里唯一无法靠"补组件"补齐的维度。

现状（0.16.0）：**123 个导出类型 100% 登记契约**
（interactive 32 · semantic 28 · decorative 63），测试 342 项（其中 a11y 21 项）。

## 2. 四件套架构

### 焦点可见性（focus-visible）

键盘操作才画焦点环，鼠标点击不画——与浏览器 `:focus-visible` 一致，避免鼠标用户的视觉噪声。
判定链：`KeyPress/KeyRelease → keyboardMode = true`，`MouseButtonPress/TouchBegin/Wheel → false`。
`NovaA11y.visibleFocus: false` 可全局关闭（截图/演示场景）。

## 3. 颜色契约：AA 兜底派生（不改品牌色）

品牌色 `primary #5B6EF5` 上压白字只有 **4.21:1**（AA 要求 4.5），`positive/warning/info`
作为文字在浅色面上只有 **2.1~2.3:1**——这是 Quasar 同款问题，靠"调品牌色"解决会毁掉企业换肤。
Nova 的做法是**派生**：本色保留给填充面与大色块，需要承载文字/边界时按最小位移压到阈值。

| 令牌 | 语义 | 明色示例 |
|---|---|---|
| `a11yBase` | 三种表面里对比度最不利的一块（派生基准） | `#F2F4F7`（page） |
| `primaryText` … `infoText` | 语义色作为文字/图标时的 AA 版 | `primary → #576AEB`（4.50） |
| `fillTint(c)` | 填充面：压到白字 4.5:1（保色相，不翻黑字） | `primary → #576AEB` |
| `outlineStrong` | 控件边界（WCAG 1.4.11 ≥3:1） | `#8C8D91`（3.00） |
| `focusRing` + `focusRingWidth/Offset` | 焦点指示（≥3:1） | `#5B6EF5` |
| `textMuted` | 次要文本（0.16.0 起自带 AA 兜底，浅色 `#6B707C`） | 4.50 |

派生是**二分求最小混合量**（22 次收敛，落点误差 <0.001）：任何 `setBrand()` 自定义品牌色都会自动
得到合规的文字/填充版本，业务侧零改动。

## 4. 组件契约：三分类（这是审计结论，不是实现细节）

| 分类 | 含义 | 强制项 | 数量 |
|---|---|---|---|
| `interactive` | 可操作控件 | `Accessible.role` + `name` + 键盘入口 + 至少一条按键路径 + 焦点环 | 32 |
| `semantic` | 只读语义元素（图表/进度/标题/链接） | `role` + `name` | 28 |
| `decorative` | 布局与装饰 | **禁止**挂 `Accessible.*`，源码须有 `// a11y: decorative` 标记 | 63 |

装饰类**故意不挂**语义：给每个容器都加 role 只会让屏读器变成噪声源（这是审计结论，不是遗漏）。
新增类型必须先在 `scripts/check_a11y.py` 的契约表登记分类，否则门禁直接报"未登记"。

### 写法范式（interactive）

```qml
    // ── 可访问性（WCAG 2.1 AA · 0.16.0）────────────────────────────
    property string a11yLabel: ""        // aria-label 等价：图形按钮必填，文字控件留空自动取 text/label
    Accessible.role: Accessible.Button
    Accessible.name: a11yLabel !== "" ? a11yLabel : text
    Accessible.focusable: !disable
    Accessible.focused: activeFocus
    enabled: !disable                    // 让 Qt 无障碍接口上报 disabled 状态（实测唯一有效途径）
    Keys.onReturnPressed: _emitClick()
    Keys.onSpacePressed: _emitClick()
    NovaFocusRing { target: root; offset: 0 }
```

`a11yLabel` 是 Nova 增强属性（Quasar 无），在 32 个 interactive 类型上统一可用。

## 5. 键盘约定

| 键 | 语义 | 覆盖组件 |
|---|---|---|
| `Tab` / `Shift+Tab` | 焦点链 | 全部 interactive（`activeFocusOnTab`） |
| `Enter` / 小键盘 `Enter` / `Space` | 激活 | Btn/BtnToggle/Chip/Item/Tab/Fab/BreadcrumbsEl/Th/ExpansionItem/Table |
| `←` `→` `↑` `↓` | 组内导航/值步进 | Tabs（受控切换）、Carousel（翻页）、BtnToggle（选项）、Slider/Range（值）、Date（日/周）、Time（时/分）、ColorPicker（色相/明度）、Table（行游标）、Pagination（翻页） |
| `Home` / `End` | 首/尾 | Tabs、Carousel、Pagination、Table |
| `PageUp` / `PageDown` | 月步进 | Date |
| `Esc` | 关闭/归位 | Menu、DialogShell、BottomSheet、Fab（收起）、SlideItem（归位）、PopupEdit、BtnDropdown |
| `Delete` | 移除 | Chip（removable） |

**受控契约不变**：键盘路径与鼠标路径走**同一个** emit 出口（`clicked()` / `updateModelValue()` /
`pageRequested()`），组件仍不自写宿主状态——a11y 不允许成为绕过受控契约的后门。

## 6. 状态播报（WCAG 4.1.3）

`NovaA11y.notice(text)` → `NovaLiveRegion` 调用 `Accessible.announce()`。单例不能直接播报是基于
QML 附加属性的硬约束（见坑位），因此拆成"状态 + 消费方"两段。

## 8. 坑位沉淀（Qt 6.12 实战，新增编号 38~41）

38. **`Accessible` 是附加属性，只能在 Item 作用域内调用**：单例（QtObject）或 `Connections` 内调
    `Accessible.announce()` 报 *"must be attached to an object deriving from Item or Action"*；
    必须落在 Item 的成员函数里（`NovaLiveRegion.speak()`）。
39. **`Accessible` 没有 `disabled` 属性**：禁用态唯一有效途径是 `Item.enabled: false`
    （实测 `QAccessible` 接口随之 `state().disabled = true`）；另有无 `defaultAction`/`ignoresAutomaticName`
    等属性同样不存在。
40. **`Keys.onEndPressed` 不存在**：Qt 6.12 只有 `onHomePressed` 级的一部分专用信号；
    `End` 必须走 `Keys.onPressed: ev.key === Qt.Key_End`（0.16.0 编译期实测）。
41. **`QTest` 键位测试要保住 `QQmlComponent` 引用**：`component.create()` 出的 `Window` 所有权属于
    组件，组件被 GC 后窗口立即析构（报 *Internal C++ object already deleted*）——测试里必须同时强引用
    组件与对象。
