## 一、一句话标准定义与三维判据定位

**NovaAgent 是一个在单次任务边界内具备自主规划与工具调用能力、但自主权随风险分级动态收束的智能体执行单元。**

> 上句为原文封版口径逐字保留；「标准」不是能力清单，而是一组**准入控制**，任何 Agent 接入企业生产环境前必须逐项通过八项检查，缺一不可。

三维判据定位（取联合方案总表 NovaAgent 列，逐字）：

| 维度 | NovaAgent |
|---|---|
| **自主程度** | 中—高（任务内自主） |
| **责任归属** | 任务发起人 |
| **交付契约** | 任务结果 + 推理链 |
| **NovaChat 角色** | 任务下发与结果回传通道 |

**可机检判据转写**（把定义落成验收动作，见第七、八章）：
- 「自主权随风险分级动态收束」→ 由业务向 `approvalSlot` 注入审批闸门，HIGH 风险动作触发 `approvalRequested()`，壳只上报意图。
- 「外部信号可核验」→ 由业务向 `verifySlot` 注入外部信号验证器，验证器独立于 Agent，Agent 无权标记通过。
- 「单次任务边界」→ 壳只托管 `taskSlot` / `planSlot` 的布局与折叠意图，不持有任务状态。

## 二、标准定义（原文完整章节，史料逐字保留）

### 2.1 封版口径

**NovaAgent 是一个在单次任务边界内具备自主规划与工具调用能力、但自主权随风险分级动态收束的智能体执行单元。** 其“标准”不是能力清单，而是一组**准入控制**：任何 Agent 在接入企业生产环境之前，必须逐项通过以下八项检查，缺一不可。

| 控制项 | 标准要求 | 封版判据 |
|---|---|---|
| **01 目的** | 任务有具体输出、明确 owner、书面边界 | 唯一验收标准是“看起来智能”则不合格 |
| **02 数据** | 明确数据来源、出境范围、保留期限 | 无法说清信息在何处终止则不合格 |
| **03 权限** | 每工具仅暴露该任务必需动作 | 以 prompt 作为唯一访问控制则不合格 |
| **04 审批** | 敏感动作有定义明确的人工复核点 | 审批对象模糊或范围过宽则不合格 |
| **05 可观测** | 可重建工具调用、返回、失败位置 | 事故后仅剩模型最终回答则不合格 |
| **06 验证** | 关闭依赖 Agent 自述之外的**外部信号** | 无文件/状态/记录可核验则不合格 |
| **07 异常** | 缺数据、阻塞、越界时有安全出口 | 系统“即兴发挥”以避免停止则不合格 |
| **08 运营** | 有负责人、消费限额、可降级/停止 | 无人知道供应商切换或事故时怎么办则不合格 |

**核心原则**：“Agent 说它完成了”不是验收信号。可验收的关闭条件只能是：文件存在且可打开、测试通过、记录状态变更至预期值、URL 可达、或来源可回溯。

> **治理归属声明**：上表八项准入控制、风险分级路由器、审批复核点、外部信号验证器均是**业务治理语义**，由业务槽位注入（见第六章）；NovaAgent 作为无业务语义骨架不实现、不判定、不代持其中任何一项。

## 三、实现方案（原文分层架构 + 全部关键实现约束，逐字保留）

分层架构（三组件共享 NovaChat 接入层）：

```
┌──────────────────────────────────────────────────────┐
│ NovaChat 接入层：会话上下文 · 身份透传 · 审计标识    │
├──────────────────────────────────────────────────────┤
│ NovaAgent 编排层                                     │
│  · 任务解析与规划（显式 DAG，非纯 Prompt 驱动）      │
│  · 工具路由（MCP / REST / 内部 Connector）           │
│  · 风险分级路由器：LOW→自动 / MED→通知 / HIGH→审批  │
├──────────────────────────────────────────────────────┤
│ 执行层：沙箱化工具运行时（最小权限，按任务发放凭证） │
├──────────────────────────────────────────────────────┤
│ 验证层：外部信号检查器（文件/API状态/DB记录/测试）   │
└──────────────────────────────────────────────────────┘
```

关键实现约束：

- **编排确定性优先**：任务的关键执行路径以显式工作流（DAG）表达，LLM 仅在需要判断的分支节点介入，避免“全 Prompt 编排”导致的不可回滚与不可追溯；
- **工具边界强制**：工具调用在沙箱中执行，凭证按任务实例动态签发，会话结束后立即失效；
- **审批不可绕过**：HIGH 风险工具在 NovaChat 中弹出审批卡片，审批记录以独立事件写入审计流，不依赖 Agent 自身日志；
- **验证器独立于 Agent**：外部信号检查器作为编排层的兄弟模块运行，Agent 无权将其标记为“已验证”。

> 上图与四条约束是**业务实现范式**史料，逐字保留；它们描述「业务侧怎么建 Agent」，不是 Shell 的槽位契约。Shell 只提供承载这些注入内容的布局骨架（第四章）。

### 3.1 异常与降级边界（新增）

| 场景 | 安全出口（业务注入责任） | 壳侧保证（可验收） |
|---|---|---|
| 缺数据 | 停止并上报「数据缺失」，不即兴补全 | `taskSlot` / `planSlot` 空注入下不溢出、稳态几何非负 |
| 阻塞 | 挂起任务、写入可追溯事件，不重试绕过 | 折叠轨 `showTask` / `showVerify` 切换不产生布局跳变 |
| 越界（工具/权限/预算） | 转人工审批，审批事件独立入审计流 | `approvalRequested()` 只 emit 意图，不自写宿主状态 |
| 外部信号验证器不可用 | 关闭条件不达成，任务不置「已完成」 | `verifySlot` 空态由业务注入，壳不塞占位 |
| 编排层（DAG 引擎）不可用 | 退化为 NovaChat 会话基座：只保留会话、身份、审计，不执行自主任务 | 壳本身即会话骨架，天然可退化，无单点故障 |

## 五、治理边界 · 无业务语义骨架（新增）

按组合组件宪法第 1 章三要素，NovaAgent 是**立于母法 L1 之上的无业务语义骨架**：由 ≥2 个已导出公共类型组合而成（组合性）、以固定语义化 `property alias` 提供单向注入点（槽位化）、不含业务菜单/路由/数据模型/文案/专属图标（无业务语义），可在 Gallery 独立预览、独立调参、独立测试。

**Shell 只托管布局与折叠意图**：八项准入控制、风险分级路由器、人工审批闸门、外部信号验证器、Shadow Mode、grounding 权限、审计埋点、用量归因等治理语义**全部由业务槽位注入**，Shell 只 emit 意图、不判定、不代持、不写宿主状态（受控契约，宪法第 3 章第 4 条）。

| 壳内可验收项（Shell 负责） | 业务注入项（槽位负责，治理语义） |
|---|---|
| 6 槽的位置 / 尺寸 / 显隐 / 断点行为 | 01 目的 · 02 数据 · 03 权限 的具体判定 |
| 两条折叠轨的展开/收起意图（emit-only） | 04 审批复核点 · 05 可观测 · 06 验证 的策略 |
| `belowBreakpoint(ro)` 自适应与 RTL 镜像 | 07 异常安全出口 · 08 运营（限额/降级/停止） |
| 身份装饰纯几何、实心度 ≥0.85、零业务语义 | 风险分级路由器 LOW→自动 / MED→通知 / HIGH→审批 |
| 明暗双主题 / `NovaMotion` 动效 / 几何钳制 / a11y | 显式 DAG 编排、工具路由、凭证签发、审计流写入 |
| 槽位宿主铺满、`overlaySlot` 透明契约 | 任务结果、推理链、外部信号、审批卡片等全部内容 |

## 九、封版声明（新增）

**正式定义（中）**：NovaAgent 是 pyside-nova 企业级旗舰版中、以 NovaChat 为统一交互基座、在单次任务边界内由八项准入控制约束的智能体任务执行工作台组合根容器，其壳仅托管布局与折叠意图。
**Formal Definition (EN)**: NovaAgent is the Agentic Task Execution Workspace composition root in pyside-nova Enterprise Flagship, grounded on the NovaChat interaction base and bounded within a single-task scope by eight admission controls, whose shell hosts layout and collapse intent only.

**封版底线**：NovaAgent 的封版底线是**八项准入控制全部通过**（原文封版结论逐字保留）。

**组件关系与不越界**（另两件见 [`LAW_NovaDE.md`](LAW_NovaDE.md) 与 [`LAW_NovaCopilot.md`](LAW_NovaCopilot.md)，原联合总纲已拆分归档为 `LAW_NovaAgent.md` / `LAW_NovaDE.md` / `LAW_NovaCopilot.md` 三份独立法源）：

| 维度 | NovaAgent（本文） | NovaDE | NovaCopilot |
|---|---|---|---|
| 自主程度 | 中—高（任务内自主） | 高（岗位内自主） | 低—中（建议 + 受限执行） |
| 责任归属 | 任务发起人 | 岗位持有者（组织角色） | 交互中的操作者 |
| 交付契约 | 任务结果 + 推理链 | 队列工作量 + 验收记录 | 建议 + 可撤销动作 |
| 身份元素 | DAG 链 / 渐变轨 / 取景框 / 审批色带 / 递减条 | 菱形徽记 / 堆叠卡沿 / SLA 递减条 / 双向箭头 | 内联胶囊 / 确认级条 / 闸门渐变点 / 撤销弧环 |
| 不越界约定 | 不持任务队列、不承载岗位形态、不内建人工确认闸门语义 | 不做单次任务自主规划、不抢占执行画布 | 不做任务自主执行、不提升 grounding 权限 |

> **收束句：治理语义由业务注入，壳不越界。** 八项准入控制、风险分级、人工审批、外部信号验证、Shadow Mode、grounding 权限等一切治理判据，均由业务向 6 个槽位注入；NovaAgent 只提供可组合、可折叠、可机检的无业务语义骨架，封版资格由母法第 13 章 API 冻结门禁授予，发布边界归 CSA。
