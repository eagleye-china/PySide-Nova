## 一、摘要

PySide6-Nova 是一套基于 Qt 原生图形引擎构建的企业级跨端组件库。它以 **139 个公共 QML 类型**
为基础、以 **15 项 Prescient Layout Shell（预判式布局壳）** 为骨架，通过统一的设计契约、
`NovaTheme` 主题令牌与 `NovaMotion` 动效令牌，在同一套代码资产下覆盖桌面客户端、移动根壳形态、
工业大屏与嵌入式终端，解决传统跨端技术栈"桌面强则移动端弱、UI 美则性能差、适配全则代码乱"
的结构性痛点。

> **一句话定位：比 Electron 稳、比 Flutter 广、比原生开发快；一套组件，全端原生级流畅运行。**

**1.0.0 GA 已封版事实**：15 项布局壳全部交付、各有独有视觉身份；API 冻结 139 类型零漂移
（指纹 `bfd3d938a2fab7be`）；静态门禁 3/3、专项 48/48、31/31 无头实例化、qmllint 0 error。
本白皮书不宣称任何"规划中"能力为已交付。

## 二、行业痛点：跨端 GUI 的结构性难题

### 2.1 多端割裂，重复造轮子

桌面、移动端、大屏往往由不同技术栈分别实现：桌面一套控件、手机一套界面、大屏一套可视化方案。
同一套业务逻辑被迫在多个代码库中重复维护，设计规范无法统一，交付成本随端数线性增长。

### 2.2 Web 壳子方案的性能天花板

Electron 类方案依赖浏览器内核渲染，空项目体积百兆起步，内存占用高、启动慢、长期驻留易出现
内存累积；对串口、CAN 总线、视频流、硬件外设等底层能力支持薄弱，且基本无法覆盖移动端与
工业大屏场景。

### 2.3 工业级稳定性与视觉表现力难以兼得

纯原生开发稳定但效率低、跨端成本高；Web 方案界面灵活但长时间运行易掉帧、崩溃。多数团队被迫
在"好看"与"稳定"之间二选一，缺少一套同时交付工程鲁棒性与美学基线的标准化组件资产。

### 2.4 骨架重复、千壳一面

即便控件齐全，业务团队仍要反复手写"Header + 侧栏 + 内容 + Footer"的页面骨架；不同页面由不同
人拼装，边距、折叠动画、主题联动、断点行为各写一套，最终 15 个壳打开像同一张脸。
**Nova 的回应是把骨架也做成产品**：15 项布局壳各自拥有独有结构性身份，且共享同一套契约。

## 四、旗舰四性标准与封版定义

### 4.1 旗舰四性

Nova 全部组件在封版前，必须通过以下四项标准验收；这既是工程质量门禁，也是品牌承诺。

| 支柱 | 英文 | 内涵 | 1.0.0 GA 落地机制 |
|---|---|---|---|
| 鲁棒性 | **Robustness** | 窗口极值、高 DPI、非法入参、动态加载、主题切换等边界场景不崩溃、有兜底 | `readonly property` 显式钳制、`Repeater`/`Loader` 动态内容、明暗实时切换、`reducedMotion` 短路 |
| 健壮性 | **Solidity** | 分层解耦、依赖定向、API 长期兼容 | `_` 私有成员不进冻结面、只 emit 的受控契约、破坏性变更走 MAJOR + 单次重签 |
| 艺术性 | **Aesthetics** | 间距、比例、圆角、阴影、动画全部取自令牌，默认即精致 | 唯一门面 `NovaTheme`、动效统一 `NovaMotion`、**15 项各自独有身份元素**、零字体依赖 |
| 前置预判性 | **Prescience** | 预判高频痛点并内置默认方案；新手开箱即用，高级用户可全量覆盖 | 安全边距 / 断点 / 主题绑定 / **Esc · Back 键盘可达** / 分层可定制 |

### 4.2 什么是"封版（Frozen）"

封版指组件对外契约冻结、门禁验收通过、纳入正式版本的状态：

- 对外 `property` / `signal` / `function` / `alias` 签名不再随意变更；`_` 私有成员不进冻结面；
- 默认美学基线与主题联动行为保持稳定；
- 后续能力只做兼容式扩展，破坏性修改必须随主版本发布并附迁移说明；
- 封版组件必须配套源码、`qmldir`、模块级 README、Gallery Demo、独立演示、单元测试与验收清单。

> **资格来源**：封版资格**只由母法第 13 章的 API 冻结门禁授予**
> （`scripts/check_all.py --tier static` 聚合），不是由文档自称 "FROZEN" 获得。
> 当前凭据：139 类型零漂移 · 指纹 `bfd3d938a2fab7be`。

### 4.3 封版红线

- 组件仅通过公开属性、信号与槽位通信，遵循单向数据流、只 emit 不自写宿主状态；
- 组合层只依赖四个基础模块与 `NovaTheme` 令牌，**不反向依赖业务代码**；
- 任意组件脱离业务项目，均可在 Gallery 画廊独立预览、调试与验收；
- 禁止硬编码业务文案、业务图标与项目专属颜色；禁止魔法 z 值与散落动画参数；
- **D-013 组合基线**：所有布局壳必须完全基于库内已导出组件组合实现，禁止私造可交互原子控件、
  复制原子样式或绕过令牌。纯几何身份装饰不构成可交互控件，不违反该基线。

### 4.4 1.0.0 GA 封版成果（旗舰实至名归）

| 成果 | 内容 |
|---|---|
| **15 项全交付** | 六类 15 项组合根容器全部落地 `Nova.Composite.LayoutShell`、全部进冻结面、全部可 Gallery 独立预览 |
| **身份差异化** | 每项独有纯几何身份元素（品牌渐变轨 / 胶囊导航台 / 中央点阵 / 下划线 / 三级色阶 / 中缝柄 / Flow 网格 / 三色条 / 侧缘轨 / 步骤时间轴 / 阅读栏 / 控制点 / 灵动岛 / 面板网格 / 六轨签名），零业务语义、零字体依赖 |
| **多轨按轨分治** | `NovaChat` 六轨每条独占前景签名，只占边缘 / 角标，中央全留给业务注入 |
| **动效全库统一** | 15 项中全部动画改为 `NovaMotion.duration()` + `easingStandard`；`reducedMotion` 无障碍短路、`speedFactor` 全库调速 |
| **键盘可达** | 可收起面板 / 浮层统一 Esc 收起意图、移动端根壳 Back 意图，全部只 emit 不夺宿主状态 |
| **契约零漂移** | 上述视觉与工程打磨全属 `_` 私有实现变更（PATCH），**公共 API 签名逐字不变、指纹不变**——恰证 Solidity 与 Aesthetics 可兼得 |
| **门禁实测** | 静态 3/3 PASS（a11y 139/139 · API 冻结零漂移 · qmllint 0 error）、专项 48/48、31/31 无头实例化、478 项 pytest 收集 |

## 五、全端覆盖能力

> 口径说明：以下描述的是**组件体系已交付的形态与能力**。平台级打包 / 真机回归记录属于后续
> 工程工作，未列入 1.0.0 GA 已验证范围，不对外宣称已完成。

### 5.1 桌面端：原生级轻量与稳定

依托 Qt 原生渲染引擎，无浏览器内核包袱：

- **毫秒级启动**，内存占用显著低于 Electron 类方案，适合 7×24 小时常驻的工具与控制台；
- 原生适配 Windows / Linux / macOS 的窗口、缩放、高 DPI、多显示器与明暗主题；
- 底层能力完备：串口、USB、CAN 总线、视频流采集、OpenGL/Vulkan 硬件加速、文件与系统服务调用；
- `NovaDesktop` 桌面根壳已交付：菜单栏、工具栏、页面宿主、状态栏、窗口控制点身份；
- 适用于开发工具、IDE 工作台、运维控制台、AI 客户端、自动化中控与企业后台。

### 5.2 移动端：一套组件编译安卓应用

不同于多数桌面 GUI 框架止步于 PC 端，Nova 的组件体系直接面向移动部署：

- 同一套 QML 组件与布局代码可打包为安卓安装包，无需另起移动端技术栈；
- 自适应横竖屏、触控手势与回弹反馈；
- `NovaMobile` 根壳已交付：`safeTop` / `safeBottom` 安全区、`NovaPlatform.isMobile` 触控判定、
  底部导航与 `backRequested` 返回意图，灵动岛 + home indicator 身份；
- **待补记录**：安卓真机打包与触控回归的验证记录（后续工程项，非本次封版范围）。

### 5.3 工业大屏：原生渲染的可视化主场

大屏与中控是 Qt 的传统优势领域，也是 Web 方案的短板：

- 原生图形引擎支持多图层叠加、海量动态数据与实时仪表盘，长时间运行不掉帧；
- 适配 4K/8K 超高清、多屏拼接与异形屏幕；
- `NovaFlexLayout` 大屏根壳已交付：`columns`（钳制 1~4）驱动浮起面板网格、`NovaScreen` 断点、
  `layoutChanged` 信号、三色面板顶条身份；
- **待补记录**：超宽 / 异形屏真机缩放回归（后续工程项）。

### 5.4 嵌入式与终端

Qt 原生跨平台底座覆盖嵌入式 Linux 与智能终端，使 Nova 组件体系具备向工业设备、触摸屏一体机
等场景延伸的潜力，而不必为终端重新设计 UI。

## 六、整体架构体系

### 6.1 分层结构

```
┌──────────────────────────────────────────────────────────┐
│  业务应用层  Business Applications                        │  业务页面 · 工具 · 数据逻辑
├──────────────────────────────────────────────────────────┤
│  组合根容器层  Prescient Layout Shell（15 项）             │  骨架 · 槽位 · 约束 · 身份
├──────────────────────────────────────────────────────────┤
│  基础组件层  Controls（91）+ Behaviors（13）               │  按钮 · 列表 · 弹窗 · 表单 · 行为
├──────────────────────────────────────────────────────────┤
│  服务与设计层  Services（16）+ Design（4）                 │  NovaTheme · NovaMotion · NovaScreen
└──────────────────────────────────────────────────────────┘
```

**五个 QML 模块**（全部随 wheel 分发，依赖严格向下）：

| 模块 | 类型数 | 职责 |
|---|---:|---|
| `Nova.Controls` | 91 | 单一职责控件、布局原语、表单与数据组件 |
| `Nova.Behaviors` | 13 | 附加交互行为（水波纹、拖拽、hover、焦点环……） |
| `Nova.Services` | 16 | `NovaTheme` / `NovaScreen` / `NovaPlatform` / `NovaI18n` 等单例 |
| `Nova.Design` | 4 | `NovaMotion` 动效令牌、a11y 设计变量 |
| `Nova.Composite.LayoutShell` | 15 | 15 项无业务语义的组合根容器 |

### 6.4 槽位契约（v2.0.0 校准）

组合层统一的是**机制与语义**，不是固定槽位名：

- 一律 `property alias` 实现，槽位是纯布局托管点，遵循单向数据流；
- 中心内容槽随骨架范式场景化命名：`contentSlot` / `gridSlot` / `pageSlot` /
  `leftSlot` + `rightSlot` / `treeSlot` + `listSlot` + `detailSlot` / `navSlot` +
  `conversationSlot` + `composerSlot` + `detailSlot`；
- `headerSlot` / `footerSlot` / `overlaySlot` 按需提供（13 项提供 `overlaySlot`，

## 七、跨端方案对比

| 维度 | PySide6-Nova | Electron | Flutter | 分端原生开发 |
|---|---|---|---|---|
| 桌面端性能 | 原生渲染，内存友好 | 内核重，内存与体积偏高 | 桌面成熟度一般 | 最优，成本最高 |
| 移动端 | 安卓打包，组件复用 | 基本不支持 | 强，移动端主力 | 各端分别开发 |
| 大屏 / 嵌入式 | Qt 传统优势领域 | 长期运行易掉帧 | 大屏与嵌入式较弱 | 依赖厂商能力 |
| 硬件 / 外设 | 串口、USB、CAN、视频流完备 | 支持薄弱 | 有限 | 完备 |
| 开发语言 | Python + QML | JS/TS + Web | Dart | 分端各语言 |
| 生态复用 | Python 数据与脚本生态 | npm 前端生态 | Dart 生态 | 各端独立 |
| 跨端一致性 | 一套组件与规范 | Web 界面统一 | 渲染自绘统一 | 需逐端适配 |
| 开发效率 | 高，低学习门槛 | 前端上手快 | 需掌握 Dart | 最低 |

> 结论：在"桌面 + 移动 + 大屏 + 硬件对接"同时出现的场景中，Qt/PySide6 路线是覆盖面与可控性
> 最均衡的选择。本表为**定性对比**，不代表具体项目的绝对性能结论；实际选型应结合团队能力、
> 交付周期与目标平台验证。

## 附录：术语表

| 术语 | 英文 | 释义 |
|---|---|---|
| 组合根容器 / 布局壳 | Layout Shell | 无业务语义的复合根容器，由 ≥2 个已导出公共类型组合而成 |
| 预判式布局壳 | Prescient Layout Shell | 内置痛点预判方案与默认美学基线的壳组件体系 |
| 根壳 | App Root Shell | 面向桌面 / 移动 / 大屏的顶层应用容器 |
| 主题令牌 | Theme Token | 颜色、间距、圆角、阴影、层叠等设计变量，唯一门面 `NovaTheme` |
| 动效令牌 | Motion Token | 时长、缓动、预设过渡与 `reducedMotion` 短路，唯一门面 `NovaMotion` |
| 槽位 | Slot | 预留内容注入点位，`property alias` 实现，遵循单向数据流 |
| 身份元素 | Identity Element | `_` 私有纯几何装饰，赋予每个 Shell 独有可辨识结构，零业务语义 / 零字体依赖 |
| 多轨按轨分治 | Per-track Identity | 多轨组件每条轨道各有独占前景签名，中央留给业务注入 |
| 受控契约 | Controlled Contract | Shell 只 emit 意图、不自写宿主状态，由宿主决定是否改配置 |
| API 冻结 | API Freeze | 公共 `property` / `signal` / `function` / `alias` 签名快照，`_` 私有成员不进冻结面 |
| 指纹 | Freeze Fingerprint | 冻结快照哈希；当前 `bfd3d938a2fab7be`，139 类型零漂移 |
| 封版 | Frozen | 对外契约冻结、门禁验收通过、纳入正式版本的状态（由门禁授予） |
| 组合基线 | D-013 | Shell 必须基于库内已导出组件组合，禁止私造可交互原子 / 复制样式 |
| 鲁棒性 / 健壮性 / 艺术性 / 前置预判性 | Robustness / Solidity / Aesthetics / Prescience | 旗舰四性验收标准 |
| a11y decorative | — | 装饰容器不挂 `Accessible.*`，避免屏读器噪声 |
| reducedMotion | — | 无障碍：动效时长归零，等价 `prefers-reduced-motion` |
| HMI | Human-Machine Interface | 人机交互界面，工业领域常用 |
