- **关键诊断结论（勿回退）**：稳态负载必须用对象池（一次建、反复操作）+ 采样前 JS(engine.collectGarbage)
  + Python 双 GC。严禁"每轮 createObject/destroy 复杂 QML 组件"当负载——实测 Qt 6.12+PySide6 每建销
  一个复杂组件有 0.3-0.5MB 不可回收固有开销，**纯 Qt Quick 组件（无 Nova 代码）同样复现**，GC 回收不了，
  真实 QQuickWindow 下亦然。属引擎层行为，不是 Nova bug；纳入会让门禁永远红灯、掩盖真泄漏。
  另：无 parent 的 QML 顶层对象在 processEvents 时被 JS GC 回收连带删 harness（坑位11姊妹），
  探针须 createObject(anchor:QObject 强引用)；Qt.createQmlObject(...,null,...) 传 null parent 会让 QML 函数静默中断。
